TABLE DETECTION + TABLE-TITLE HEADER - DETECTION-ONLY CHECK (2026-11-18)
Dev data only. No embedding, no ingest, no LLM, no Cloudflare. Qdrant read-only scroll of eval-ragbench-dev-20261115.
Files: build-cache.mts (load + chunk like the pipeline, compare with Qdrant), tableHeaders.mts (detector, FROZEN),
run.mts (stats, gap coverage, FPs, sample), stats.json, sample.txt (50 tables + 3M), fp-examples.txt, verdicts.json, peek.mts (debug).

1. REPRODUCTION
   loadDocument + chunkText(recursive, 500, fixHeadingSplit) per page gives exactly the stored chunk texts:
   FB 73,879/73,879, tat 19,288/19,288, nq 908/908, feta 2,945/2,945 (96 docs, 97,020 chunks, 100%).
   The header never changes chunk text or boundaries (it would only be prepended for embedding, like payload.section).

2. FROZEN SETTINGS (tuned by eye on page dumps only; relevance labels never used for tuning)
   row: line ends with number-like tokens, label <= 14 words (<= 25 if it ends with >= 2 numbers), not a sentence;
   wrapped label lines merged into the row (up to 3 lines). label line <= 6 words (<= 8 if ends with ':').
   table: >= 3 rows, gap <= 1 non-row line, <= 5 label lines in a row. sentence = ends '.' with >= 6 words; prose >= 16 words.
   end: sentence, >= 2 non-row non-label lines, or a new title block (units line, or name + period line, <= 4 lines) then rows.
   title: walk up <= 8 lines on the same page; stop at blank/row/sentence; keep ':'-ending lead-ins and wrapped lead-ins;
   if units/period lines exist: <= 2 name lines above them + those lines; else last 2 lines; drop "(Unaudited)"; cap 200 chars.
   skip: page-edge lines (first/last 3) repeating on >= max(3, 20% of pages), page numbers, "Table of Contents";
   TOC filter (>= 80% rows end in one non-decreasing integer <= 500). Untitled table <= 3 lines after another is merged into it.
   chunk: header of the table covering most of the chunk; none if the chunk holds that title or touches no table.

5. FALSE POSITIVES (non-table-like relevant chunks that get a header)
   FB 97/904 (unique 84/746, ~11%), tat 58/1,265 (unique 41/1,029, ~4%).
   Read 50 of them (fp-examples.txt): practically all are real tables the diagnosis heuristic missed (dot-leader rows
   like Adobe's balance sheet, the last rows of a table before prose, EPS/tax-rate rows). Not one was clearly a non-table;
   about 5 had a weak header (column words or a row label). So the true "header on a non-table" rate here is close to 0.
   In the 50-table sample, 5 detections were not tables (footnote markers (1)(2)(3) x3, a chart axis, a Wikipedia infobox);
   3 of those 5 had no title so no chunk gets a header; the other 2 headers are short junk.

8. FAILURE PATTERNS
   - No table name, only units/dates/columns (most "partly"): the name sits further up or in a section heading.
   - Long lead-in sentences hit the 200-char cap or start mid-sentence.
   - Header taken from rows of the table above (Nike t49) when two tables touch.
   - Wrapped rows/footer glued to a row end the table early (Boeing EPS rows, Pfizer products, George Weston).
   - Footnote-marker columns and chart axes detected as tables (mostly no title, so harmless).
   - Wikipedia PDFs: cells wrap over many lines; titles are fragments. Do not use headers for nq/feta.

9. RECOMMENDATION
   For financial filings detection is good enough to test: 89% of FB and 60% of tat untitled table chunks would get a
   header, almost always with units and a period, and headers on non-tables are rare. Titles are fully right only ~1/3 of
   the time, so expect a modest gain, not a fix. Suggestion: if the re-ingest is done, enable it only for filings-like
   docs (or skip headers for Wikipedia-style PDFs) and first try a cheap partial check: re-embed only the ~6,700 headed
   FB+tat chunks into a copy collection instead of the full 7-8 h re-ingest.
