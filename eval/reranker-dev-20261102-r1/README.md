# RERANK-1 dev experiment

Run `node eval/reranker-dev-20261102-r1/prepare.mjs` once to freeze the sample and saved-pool hashes. It reads only existing dev candidate records and split metadata, does no retrieval or inference, and refuses to overwrite artifacts. Twenty cases are selected deterministically, ten omissions and ten acceptable cases, before reranker outcomes; dense and hybrid pools are both retained. All 459 saved cases per mode contribute to the recorded baseline item metrics.

Live execution is pending: the active provider token could not read subscriptions or billable usage (HTTP 403/code 10000), so neither enforced free-only protection nor remaining shared daily allowance was established. **Zero hosted inference calls were made.** There is deliberately no executable live dispatch path until that prerequisite is resolved and the coordinator authorizes it. The historical October authorization/ledger is not reused.

The future authorized runner must count each attempt in `attempts.jsonl` before dispatch, record model, request bytes, candidate counts, latency, failure and available usage evidence, run serially without retries, stop on auth/quota/rate/contract errors, and use at most four synthetic requests plus these forty dev pools. Empty pools consume no request. Synthetic checks should include representative long preserved inputs; the hosted truncation policy remains unverified. Numerical call limits do not guarantee free use.

For future complete rerank permutations, `reranked-results.jsonl` uses `{caseId,mode,indices}` where indices list original saved candidates in rerank order, including all candidates. `node eval/reranker-dev-20261102-r1/report.mjs` validates input hashes and sample identity, then computes recall@5/10/20/50, MRR, item gains/regressions and any-item case gains/regressions separately by omission/acceptable and quote length. It uses the original A/P gold and the established exact whitespace containment OR verified same-paper range-overlap matcher; it reads extracted source only after verifying dev membership. Missing results are reported as pending, never simulated as real gains. No answer quality conclusion follows from an item hit.

Baselines: [A/P](../ap-query-form-20261102/RESULTS.md), [Q hybrid](../question-only-same-paper-20261102/RESULTS.md), [Q dense](../q-dense-vs-hybrid-20261102/RESULTS.md). Q hybrid cutoffs are slices of a single k50 ranking whose prefetch depends on k.
