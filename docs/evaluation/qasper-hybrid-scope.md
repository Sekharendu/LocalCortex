# Document scope and independent hybrid arm (QH-SCOPE-1)

The approved change restricts retrieval when the user explicitly names a document. It does not change the generation persona, prompts, model, chunking, relevance threshold (0.63), follow-up floor (0.57), or weighted RRF (dense 2: sparse 1).

The literal grammar recognizes filenames (`report.pdf`, `"Annual Report.pdf"`), quoted titles after `paper`, `document`, `report`, `bulletin`, `title`, or `file` (optionally `called`, `named`, `titled`), and capitalized names ending in Bulletin, Handbook, Policy, Report, Document, Paper, or Manual after in/from/regarding/using/about/the. Attached `version`, `revision`, `rev`, `v` numbers and `effective YYYY-MM-DD` dates must match the indexed header/source. Generic topics and model versions alone do not select a document. Arbitrary prose, incomplete names, spelling correction, aliases, and general document-identity NLP are not promised.

Resolution uses live Qdrant chunk-zero source and title/header prefixes, normalizing Unicode punctuation, whitespace and line-end hyphenation. It does not consult QASPER annotation IDs or gold targets. A missing or ambiguous reference/version returns no context; it never substitutes a similar document or selects an arbitrary latest version. Multiple named documents require a unique identity for each. Catalogs are request-local, capped at 4,096 headers with 128-record pages and no vectors. A catalog failure propagates as an infrastructure error. Referring follow-ups retain the original user reference before rewriting; independent questions end inheritance and new explicit references replace it.

Scope filters apply to dense/follow-up probes, same-document fill, both hybrid prefetches and final fusion. Context expansion only loads the selected document IDs. Deletion committed between resolution and search cannot cause cross-document fallback. This does not promise serializable revocation once context has already been captured.

The new `scripts/evaluation-hybrid-20261029` tooling is an independently copied safety harness. Its preparation selects exactly the existing 871 case IDs and original actual wordings (708 PDF, 163 DOCX), including the four old errors. It copies document/sparse metadata, never old attempts/results/provider ledgers. Existing dense tooling and results remain sealed. The new manifest captures current source/tool hashes and old input identities; the runner explicitly requests `mode: 'hybrid'`. Only answer and summary stages are enabled; no ingestion/reembedding is required.

Before hosted execution, seal the new arm, run `retrieval-comparison.mjs --stage scope` for each format, and review the source and guards. `retrieval-comparison.mjs` without `--stage scope` performs a generation-disabled dense/hybrid comparison on the same new application source, recording scope decisions and actual hits. The scope-only audit records a timestamped bounded live catalog snapshot; the retrieval comparison resolves live per question. Both preserve exact case wording. Expected literal-title mismatches must remain visible, rather than being masked by a gold-document filter.

The old dense answers versus new scoped hybrid answers measure a combined application change. The same-source local retrieval comparison isolates retrieval mode; it does not establish answer accuracy. Lexical overlap/evidence matching remain diagnostics, with independent semantic grading pending. The previous 200-case reference rubric, dataset/PDF revision uncertainty, unavailable table/figure content and generated-DOCX limitations continue to apply.

Hosted execution remains one outstanding request, the existing free-only model, durable reserve-before-send ledger and same-day deadline 2026-10-29T18:30Z. The runner stops at the first quota/rate/auth issue, with unknown usage retained; no paid capacity, automatic retry, reset or next-day continuation. Reviewer readiness is required before the coordinator starts it.
Run hosted formats sequentially in separate processes (explicit --format pdf, then --format docx), so each imports its own frozen SPARSE_STATS_PATH and DOC_STORE_PATH. An exclusive answer-driver.lock plus the one-outstanding-request ledger prevents concurrent hosted drivers. A crash leaves the driver lock fail closed for inspection; do not steal a possibly live lock.

R2 identity hardening: title identity now requires complete leading title lines, rather than a substring anywhere in the first paragraph. Only up to two anchored arXiv preprint stamps or `Under review as a conference paper at ... YEAR` lines may precede the title. Arbitrary author lines, other titles, prose, page folios and other publication frontmatter are not skipped. Revision identity comes from the source filename, actual leading title, or consecutive standalone Version/Revision/Effective fields immediately below it; unrelated body/model versions cannot qualify it. Conflicting actual revision fields fail closed. Direct referring revision/date requests retain inherited constraints, so a changed qualifier fails closed until a new explicit document reference replaces it. Generic model-version followups remain ordinary topic text.

The final R2 scope audit resolved 845/871 cases (682 PDF + all 163 DOCX); 26 PDF cases are unavailable under this conservative grammar. Eight are previously identified literal title typos. Eighteen have unsupported leading layouts or an omitted title suffix: author-before-title (4), report-cover frontmatter (2), other venue headers (4), leading page folios (6), and omitted Student Abstract suffix (2). All 871 remain in the execution queue. This trades unsupported-layout recall for protection against substituting a mentioned document under another title.

R3 qualifier correction: revision/effective-date qualifiers anywhere in a referring turn are carried with the inherited document constraint, including `Does that change in version 2?`. Pending qualifiers survive intervening referring turns. Explicit model-version topic phrases are excluded. Filename aliases derive the actual bounded leading title/metadata boundary independently of the filename, so wrapped title metadata cannot hide a conflicting revision. Uncertain filename/title boundaries fail closed. The sealed R3 audit remains 845 resolved / 26 missing, with all 871 cases retained.
